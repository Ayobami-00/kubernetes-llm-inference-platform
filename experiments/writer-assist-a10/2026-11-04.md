## Transport diagnosis and follow-up condition

Gateway logs identify the retained 503s as
`upstream_reset_before_response_started{connection_termination}` with `UC`, against
the model endpoint. The pinned installed vLLM source uses a five-second HTTP
keepalive; the installed gateway CRD documents a one-hour default upstream idle
timeout. A route-scoped three-second idle timeout was accepted **after** the pair,
with no retries added. This tests idle connection reuse as the cause; acceptance
alone does not prove the fix. Subsequent validation has a distinct run identity
and pins the policy content before freezing its snapshot. The first pair is not
rewritten or silently re-scored.
